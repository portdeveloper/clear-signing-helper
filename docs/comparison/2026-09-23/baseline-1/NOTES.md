## Decisions (made by me because the user was not available)

1. **Entity folder `puddleswap`.** Lowercase, like most existing entity folders. `metadata.owner` = "PuddleSwap", as the task specified.
2. **File name `calldata-StakingRewards-USDC-WMON.json`.** The source says "One instance per farmed pool". Because the staking token is hard-coded as a constant in this descriptor, each future pool instance needs its own descriptor. The pool name in the file name keeps those future files distinct. The version/pool lives in the file name, which follows the registry's convention.
3. **Amounts in `stake` / `withdraw` use `stakingToken`** (USDC/WMON UNI-V2 LP). I checked this in the source: `stakingToken.safeTransferFrom(msg.sender, …, amount)` and `stakingToken.safeTransfer(msg.sender, amount)`. Both tokens are `immutable`, so a constant (`$.metadata.constants.stakingToken`) is exact and cannot drift.
4. **The LP token's on-chain symbol is the generic "UNI-V2".** On its own it doesn't say which pool the user is staking in. So the field label is "USDC/WMON LP amount" and the interpolated intent adds "(USDC/WMON)", for example "Stake 1 UNI-V2 (USDC/WMON)". I did not try to override the symbol, because wallets take the ticker from their token metadata.
5. **`notifyRewardAmount` amount uses `rewardsToken` (WMON).** Its `reward` is denominated in the rewards token (`rewardRate = reward / rewardsDuration`, checked against `rewardsToken.balanceOf(this)`). Intent: "Start reward period". This call does not move tokens (they must already have been sent to the contract), so I deliberately avoided wording like "Deposit" or "Fund".
6. **`getReward` / `exit` have no parameters.** Their intents name what happens: "Claim WMON rewards", and "Unstake all and claim" (interpolated: "Unstake all and claim rewards"). The source confirms that `exit()` = `withdraw(full balance)` + `getReward()`. Hard-coding "WMON" is safe because `rewardsToken` is immutable.
7. **`recoverERC20` shows all three parameters:** Amount (as a token amount, via `tokenPath: #.token`), the Token address, and the Recipient. I show the token address as well as the ticker because a ticker alone can be spoofed. Intent: "Recover stuck tokens". (The contract refuses to recover the staking token, but that is not something the descriptor needs to show.)
8. **The `setRewardsDuration` value uses the `duration` format.** Runners render it as HH:MM:SS, so 14 days shows as "336:00:00". That is spec-conformant but not very friendly. The alternative, `unit` with base "s", would show "1209600s", which is worse.
9. **Role management (`grantRole`, `revokeRole`, `renounceRole`) is included.** Admin and operator signers deserve clear signing too, and leaving these out would make wallets fall back to blind signing for the most dangerous calls. The role is shown as the **raw bytes32 hash**. My first attempt used an `enum` that mapped the hashes to "Admin role" / "Operator role", but both CI runners fail it (see fix iteration 2): the spec defines `enum` only for integers, and the Sourcify library rejects non-integer values. For reviewers and signers, the two known hashes are:
   - `0x0000…0000` = DEFAULT_ADMIN_ROLE (full control: can grant/revoke roles, recover tokens, change the duration)
   - `0x97667070…b929` = OPERATOR_ROLE (can start reward periods)
10. **Nothing is hidden (no `visible: "never"`).** Every parameter of every function is displayed. For `renounceRole`, `callerConfirmation` must equal `msg.sender`, so it could be hidden defensibly. I kept it visible as "Your account" with `types: ["wallet"]` so wallets can check that it is the signer's own address.
11. **Every format has an `interpolatedIntent`** (the registry's recommendations check asks for this). Each one is kept to 30 characters or fewer as written in the template, because the linter warns above 30 for Ledger devices. That limit forced terse wording in a few places: "Grant role to {#.account}", "Revoke role from {#.account}", and "Period of {#.rewardsDuration_}". Role hashes are left out of the grant/revoke sentences because a 66-character hex string would swamp them; the hash is still shown as its own field.
12. **`metadata.info.url` = `https://puddleswap.org`.** I found it via a web search (a dev.to post by the author says "live at app.puddleswap.org"); both puddleswap.org and app.puddleswap.org return HTTP 200. `deploymentDate` is the timestamp of the deployment block.
13. **Only state-changing functions are included.** View functions are never signed, so they are left out.
14. **Test fixtures.** 5 cases are real on-chain transactions, re-serialized as unsigned EIP-1559 txs, with `txHash` included:
    - `stake`: `0x7bf3f021…f8f0`
    - `getReward`: `0xe5b8c9c9…fc8c`
    - `withdraw`: `0x783edb0d…7e29`
    - `notifyRewardAmount` ×2: `0x32544fc1…24af` (1000 WMON) and `0xe93c2160…96fc` (1 WMON)

    I proved each unsigned re-serialization is faithful: adding back the on-chain r/s/yParity reproduces the exact tx hash (`tools/verifyreal.mjs`, all 5 MATCH). The other 8 cases are synthetic, because I found no real txs for those functions: exit, setRewardsDuration (14 days), recoverERC20 (5 USDC), grantRole operator, grantRole admin, revokeRole, renounceRole, and stake of exactly 1 LP. The synthetic txs use chain 10143, the real contract address, the real token addresses, and the deployer address. The third-party grantee is `0x70997970C51812dc3A010C7d01b50e0d17dc79C8`, a well-known test address.

### Fix iterations

1. **Lint length warnings** (check 3).
   - Label → "USDC/WMON LP amount" (19 chars).
   - Enum values → "Admin role" / "Operator role" (the enum was later removed in fix 2).
   - Interpolated intents rewritten to ≤30 chars, for example "Stake {#.amount} (USDC/WMON)" and "Recover {#.amount} to {#.to}".
   - Temporarily dropped the interpolatedIntent of setRewardsDuration, because no ≤30-char wording seemed possible.
2. **Runners: 4 role tests failed on both implementations** (check 9). `enum` on `bytes32` isn't portable. The Sourcify library only accepts uint/int/bool for enum (`typeMismatch … "uint, int or bool"`) and fell back to hex. The Rust runner converted the value to decimal and found no key.
   - Changed the role fields to `format: "raw"` and removed `metadata.enums`.
   - Removed the role from the grant/revoke interpolated intents.
   - Updated the expected values.
3. **Recommendations advisory** (check 16): setRewardsDuration had no interpolatedIntent. Added "Set {#.rewardsDuration_} period".
4. **Lint warning** (check 17): that template is 31 chars (I had miscounted it as 30). Changed it to "Period of {#.rewardsDuration_}" (30). I rejected "epoch" because it would be confused with Monad consensus epochs.
5. **Formatter** (check 20): `erc7730 format` reflows short objects onto one line. I adopted the formatted output for both files (verified semantically identical with a JSON deep-equal), so the registry's weekly format bot won't touch them.

Total: **5 fix iterations**. The failed log scan (row 5) and the script bug (row 21) were problems with my own tooling, not failures of the deliverable, so they are not counted.

## Could not do / could not verify

- **Ledger device tests were not run.** They are disabled in the registry CI, because the Ledger coin-apps repo is private. The Ledger-specific length rules were only checked via the linter's warnings.
- **The PR-only CI steps can't run locally**: the `tj-actions/changed-files` detection, the artifact/comment workflows, and the `SOURCIFY_TOKEN` authenticated fetch. I reproduced their logic with the same scripts, and the same file lists they would compute.
- **Real txs were not found for 6 functions** (exit, setRewardsDuration, recoverERC20, grantRole, revokeRole, renounceRole). No explorer API was usable without credentials, historical state is pruned, and I scanned only ~100k of the ~25M blocks since deployment (the windows right after deployment and right before the last notify). Real txs for those functions may exist elsewhere in history. The synthetic fixtures are valid unsigned txs, but they are not on chain.
- **The rendered role is a raw 32-byte hash**, which is not user-friendly. There is no portable ERC-7730 way to label bytes32 constants today. A human reviewer could reasonably prefer leaving the role functions out, but I judged showing them better than blind signing.
- **The `duration` rendering "HH:MM:SS"** (e.g. "168:00:00" for 7 days) comes from the two CI runners. Other wallets may render it differently.
- **I'm unsure about the `url`**: puddleswap.org (landing page) vs app.puddleswap.org. The PuddleSwap team should confirm.
- **Noise in CI logs:** cs-test prints "failed to parse descriptor …/sigs/…" warnings for other entities' attestation files. These already exist on master, are unrelated to this PR, and don't affect results.
- **Possible review question:** this would be the first descriptor for chain 10143 (Monad testnet). The registry already contains testnet descriptors (Sepolia 29, Base Sepolia 2, Arbitrum Sepolia 2), so I don't expect this to be a blocker.
