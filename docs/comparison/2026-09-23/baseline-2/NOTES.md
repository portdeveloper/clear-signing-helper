# PuddleSwap StakingRewards — ERC-7730 registry submission notes

Contract: `0xe23B3825F950637256e8DE1BF39743E8f29D97F1`, Monad testnet (chain 10143), verified on Sourcify
(full match, `src/StakingRewards.sol:StakingRewards`, solc 0.8.35). Synthetix-style single-pool LP farm:
stake a PuddleSwap Uniswap-V2 LP token, earn WMON.

## Decisions (made without the user) and why

1. **Entity folder `puddleswap`**: lowercase protocol name, the same convention as most entity folders (`uniswap`, `quickswap`, …).
2. **File name `calldata-StakingRewards-USDC-WMON-monad-testnet.json`**: contract name + pool + network. The source
   says "one instance per farmed pool", so later pools will need their own files; naming the pool and the network
   avoids a collision (the existing testnet precedent is figment's `…-sepolia`).
3. **One self-contained file rather than a `common-*` file plus a per-pool file.** Only one deployment exists. Risk:
   when a second pool ships, factoring out a common file means editing this descriptor, and CI blocks changes to
   an attested descriptor. At that point the cleaner path is a new `common-` file plus new per-pool files, leaving this one as is.
4. **Owner `PuddleSwap`** (given). **URL `https://puddleswap.org`**: found via web search (the DEX app is at
   app.puddleswap.org); both return HTTP 200. `contractName` = `StakingRewards` (the Sourcify contract name).
   `deploymentDate` = timestamp of the deployment block.
5. **Token denomination.** `stake`/`withdraw` amounts are in `stakingToken` and `notifyRewardAmount` is in `rewardsToken`.
   Both tokens are `immutable` in the contract and do not appear in calldata, so they sit in `metadata.constants` and are referenced with
   `"token": "$.metadata.constants.…"`. `recoverERC20`'s amount uses `tokenPath: "token"` (the token being recovered).
6. **Naming the pool in stake/unstake intents.** The LP token's on-chain symbol is the generic `UNI-V2`, so a wallet
   would show "Stake 0.0000175 UNI-V2" with nothing to identify the pool. The descriptor is bound to one address with an
   immutable staking token, so hardcoding the pool name is accurate. Intents are `Stake USDC/WMON LP` / `Unstake USDC/WMON LP`,
   and interpolated intents are `Stake {amount} (USDC/WMON)` / `Unstake {amount} (USDC/WMON)`.
7. **Intent wording** (all ≤ 30 characters and labels ≤ 20, so nothing is truncated on Ledger. See fix iteration 1):
   - `getReward()`: "Claim rewards" / "Claim WMON staking rewards"
   - `exit()`: "Unstake all and claim rewards". `exit` takes no arguments (it withdraws the full balance), so it has no fields.
   - `notifyRewardAmount`: "Start reward period" / "Start {reward} reward period". Per the source, this starts or extends a
     `rewardsDuration`-long period using tokens already sent to the contract. It moves no tokens itself.
   - `setRewardsDuration`: "Set reward period duration" / "Set period {rewardsDuration_}", using the `duration` format
     (HH:MM:ss, so 14 days renders as `336:00:00`). That is readable but not pretty. `unit` with base `s` would render `1209600s`, which is worse.
   - `recoverERC20`: "Recover tokens" / "Recover {amount} to {to}"
8. **Admin and AccessControl functions are included** (`notifyRewardAmount`, `setRewardsDuration`, `recoverERC20`,
   `grantRole`, `revokeRole`, `renounceRole`). Admins and operators sign from wallets too, and role changes are the most
   dangerous calls on this contract. Leaving them out would mean blind signing for exactly those calls. All 10
   non-view functions in the ABI are covered.
9. **Role display = `raw` bytes32 hex.** The spec defines `enum` only for integers, so mapping `0x9766…` → "Operator" would
   be off-spec and might not work across wallets. The signer sees the hash. The mapping is in the table above.
   This is the weakest part of the UX, and I chose it for spec compliance.
10. **Nothing is hidden** (no `visible: never`). Every amount, recipient and account is shown. `renounceRole`'s
    `callerConfirmation` (must equal the signer) is shown as "Account" but left out of the interpolated intent to keep it short.
11. **Address fields** use `addressName` with `types: ["eoa","contract"]` and `sources: ["local","ens"]`: a recipient or role holder can be either kind.
12. **Tests**: 4 real transactions (stake, withdraw, getReward, notifyRewardAmount, all sent by the deployer, found by scanning
    `eth_getLogs`) and 6 synthetic unsigned transactions (exit, setRewardsDuration, recoverERC20, grant/revoke/renounceRole),
    marked "(synthetic)" in their descriptions and without a `txHash`. The dataProvider lists on-chain token metadata.
    For the real txs, the unsigned re-serialization was checked: re-signing it with the original r/s/yParity reproduces the on-chain tx hash (`hashCheck: true`).

### Fix iterations

1. **Lint warnings**: "Display intent too long" (> 30 chars, may be truncated on Ledger) for 5 interpolated intents, and
   "Display label too long" (> 20) for 2 labels. Shortened: `Unstake all and claim rewards`, `Renounce role {role}`,
   `Revoke {role} from {account}`, `Start {reward} reward period`, `Set period {rewardsDuration_}`, and labels
   `Reward amount` and `Period duration`. Re-lint: no issues.

Other revisions that did not come from a failing check: whitespace normalization by `erc7730 format` (check 11), and
naming the pool in the stake/unstake intents (decision 6). Everything was re-run afterwards and still passed.

### Could not do / could not verify

- **Real txs for 6 of 10 functions**: the Monad public RPC caps `eth_getLogs` at 100 blocks. Explorer APIs were
  unavailable without keys (Etherscan v2 needs a key, socialscan returned 503, Routescan doesn't support the chain,
  Envio HyperRPC needs a token). I scanned the first 330k blocks after deployment (≈3.3k requests) and found only the 4
  deployer txs. The rest of the ~24.7M blocks were not scanned, so exit/admin/role calls use synthetic txs.
- **Ledger runner**: disabled in the registry's CI (private binaries), so it was not run. Not tested on a real device.
- **CI's `SOURCIFY_TOKEN`**: the local lint ran without it and fetched the ABI fine. CI should behave the same.
- **`analyze.yml`**: manual `workflow_dispatch` only, needs LLM API keys. Not run.
- **Advisory comment and PR labeler**: not run as GitHub Actions, but the recommendations script (check 8) was run and gave empty output.
- I did not ask PuddleSwap to confirm the URL, the intent wording, or whether they want the admin/role functions included.
