Clear Signing Helper

Wallets show raw hex unless a protocol has published an ERC-7730 descriptor in the Ethereum Foundation's registry. This tool takes a contract to that registry submission: it derives what the ABI, compiler output, deployment records and verified source prove, asks a human only for what they cannot, and runs the registry's own checks before you open the pull request. Every claim on this page links to the code behind it.

What this tool does, and does not do

The tool DOES

  • Derive functions, argument paths, types and selectors from the ABI, and reject a descriptor whose paths do not exist (descriptors.ts).
  • Render every example transaction through the pinned Sourcify renderer and write the rendered text, not typed text, into the registry test file (fixtures.ts, registry.ts).
  • Reject calldata that does not re-encode byte for byte, so appended or malformed bytes never pass (NONCANONICAL_CALLDATA).
  • Require a payable function to display its native value (UNDISPLAYED_NATIVE_VALUE).
  • Verify the vendored renderer's hash on every build (verify-renderer.mjs).
  • Run the registry's formatter and linter on export when uvx is present, and produce no bundle when lint reports an error (lint.ts, exportBundle).
  • Run the registry CI's Sourcify and Rust implementations on the exported tests when asked, and fail the export if any case fails (runners.ts).
  • Prove an address before adding it to an existing descriptor: by selectors against the verified ABI for calldata, by the live DOMAIN_SEPARATOR() for EIP-712 (ABI_MISMATCH, DOMAIN_MISMATCH).
  • Record where every generated value came from: NatSpec, AST, broadcast, convention, registry prior, human or model (provenance).
  • Invalidate a recorded review when source, ABI, descriptor, exclusions or build settings change (reviewFingerprint, build fingerprint).
  • Prefill intents and labels from NatSpec when they fit a device screen, and say when they did not (scaffoldFormatWithProvenance).
  • Apply the registry's conventional formats to ERC-20 and WETH-shaped contracts, marked as conventions and editable (ERC20_CONVENTIONS).
  • Warn, rather than fail, where the renderer itself only warns: an undisplayed argument, an intent over 30 characters, a type mismatch, a disagreement with every registry descriptor for the same selector (warnings, priors.ts).
  • Reject known wallet incompatibilities under --strict-portability: signed integers, nested arrays, multi-field tuple arrays (portability.ts).
  • Embed the compiled ABI in the descriptor on request; off by default because the schema deprecates it (--inline-abi).

The tool does NOT

  • Guess what a function does, which token an amount is denominated in, or which arguments to hide; those are left raw or asked for (writeDecisions).
  • Bind a deployment on a contract name alone; bindings come from broadcast records, from verified source, or from the author (deployedContracts, fetch.ts).
  • Accept an unverified address as a source of an ABI without saying so (SOURCE_UNVERIFIED).
  • Re-encode, trim or repair calldata (fixtures.ts).
  • Write a descriptor, test file or configuration when validation fails; failures leave files untouched (applyDecisions, registry-edit.ts).
  • Sign, send or simulate transactions, hold keys, or open pull requests (README).
  • Touch the network except for init --address, registry add-deployment (Sourcify, or read-only calls to an RPC endpoint you name), the upstream lint and format run, and the one-time runner build (recorded decision).
  • Author new EIP-712 descriptors; it only adds a chain to an existing one.
  • Decode nested calls (the calldata format) or encrypted fields; both are rejected explicitly (UNSUPPORTED_FORMAT).
  • Verify deployed bytecode beyond a Sourcify match, or discover proxies beyond what Sourcify resolves.
  • Prove that a description is semantically true. The registry's own review guide assigns that to auditors; this tool records who decided and why (what still needed a human).

Get started

# Node 22+. Foundry only for Foundry projects. uv enables the registry's linter.
npm install --global --ignore-scripts clear-signing-helper@preview

# From a verified address
clear-signing init --address 0xYourContract --chain-id 143 --owner "Your Protocol"
clear-signing decisions --contract clear-signing/abi/YourContract.json:YourContract
#   fill intents, denominations, show/hide, exclude; set "author"
clear-signing apply --decisions clear-signing/decisions/YourContract.json
clear-signing fixture --name stake --contract <id> --function 'stake(uint256)' --args '["1000000000000000000"]' --chain-id 143 --to 0xYourContract
clear-signing preview --fixture clear-signing/fixtures/stake.json
clear-signing review --accept && clear-signing test --update
clear-signing export --strict-portability --registry-runners --out bundle

# Protocol already in the registry, new chain
clear-signing registry add-deployment --registry ./registry-clone \
  --descriptor registry/weth/calldata-weth.json --chain-id 143 --address 0x... --token 0x...=WMON:18

Inside a Foundry repository, forge build once, then clear-signing init; the tool also reads NatSpec, enums and broadcast records there. Full command reference in the README; the agent playbook is the skill.

Use Cyfrin's tool to read what a transaction does or to compute Safe and ERC-8213 hashes, Ledger's builder for a device-shaped preview in a browser, erc7730 to author EIP-712 descriptors, and this tool for the last mile the others stop before: the test file, the registry's own checks before the PR, and the one-command chain addition.

Status

  • Published: 0.3.0-preview.1 on npm and as a GitHub prerelease, byte-for-byte identical (release record, verification script).
  • First real submission: registry PR #3003, a staking contract on Monad testnet, produced entirely by the tool. All 13 registry checks passed on the first push; maintainer review pending (dogfood record, including what still needed a human).
  • Measured against the registry: the validator accepts 261 of 284 merged descriptors; the rest use nested-call or encrypted fields, which are out of scope by design (acceptance script, recorded run).
  • Tested: 48 automated tests (test/, CI), the registry's full corpus of 283 descriptors and 605 real transactions (registry-compatibility.test.ts), a mined Anvil deposit (anvil.test.ts), and a mocked Sourcify for offline CI (abi-mode.test.ts).
  • Not yet: authoring new EIP-712 descriptors, and a cold run by a team that did not build it (roadmap).
